# Publication proof contract

Generated and legacy drafts use one publication contract. `aiAssisted`, `generatedAt`, and quality-version labels establish provenance; they do not establish approval. Publication does not make another provider call.

Explicit validation records a `publicationProof` containing the complete ordered lesson scope, candidate content hash, current policy version, deterministic quality/grounding report, moderation-evidence fingerprint, and a successfully executed local safety scan. Missing historical generation moderation is reported as `CQ_SAFETY_001`, requiring explicit owner safety review. A blocked, edited, wrong-scope, or outdated generation proof is `CQ_SAFETY_002`, an independent non-overridable blocker. A local scan is never labeled as provider moderation.

Successful generation may retain its actual output-moderation evidence through `createGenerationSafetyProof(finalPayload, "course")` or `createGenerationSafetyProof(finalPayload, "lesson:<id>")`. Store its result in `generationSafetyProof`. Call it only after output moderation succeeds, after every final content/provenance field is assigned, immediately before the guarded save. The helper makes no provider call. Changes after proof creation invalidate it. Source-grounding decisions continue to be validated against the source policy and exact source/outline/lesson relationships; source assignment is not factual verification.

Validation reuses genuine moderation evidence and runs current deterministic quality and grounding checks. Unexecuted semantic, claim-support, accessibility, and asset checks remain explicit manual issues. High-stakes source-evidence requirements remain enforced by the owner manual-review route. No quality override can waive structural, source-security, stale-proof, or other independent blocking rules. The recently authenticated owner decision binds the content hash, quality contract, publication policy, and exact proof evidence. Revalidation with changed evidence returns the draft to manual review. Legacy drafts use the same existing validation/manual-review API; V2 pauses still close V2 publication.

The transaction rereads the draft and every outlined lesson, checks the full proof and source fingerprints, recomputes the candidate hash, checks quarantine/V2 pause state, and verifies the current manual resolution. It commits visibility, decisions, proof, and immutable course/lesson release records together. Release identity includes both content and review evidence. A retry key publishes once; explicit unpublish supersedes that retry. Learners read the committed immutable release, including when subsequent draft writes occur.

`publicationProof` and `generationSafetyProof` are excluded from document content hashes to avoid self-reference. Their evidence is bound separately; root metadata exclusions never apply to nested content IDs. Manual review and local proof timestamps do not make repeated identical validation invalidate an otherwise current approval.

Generation-route producer wiring, authoring visibility of the legacy validation/review controls, source-research freshness integration, real PostgreSQL race verification, hosted runtime review, and candidate-SHA CI are separately recorded integration/release gates. Historical publications are not silently re-certified; this contract governs new publication commits.

Manual review also requires the exact `proofToken` returned alongside the validation report. This is a 64-character lowercase SHA-256 token over canonical approval evidence, excluding validation/scan timestamps. The owner request submits it unchanged; both the request handler and atomic writer compare it before saving or replaying a decision. The saved resolution, audit event and idempotency record retain the token. A mismatched token returns `409 STALE_PUBLICATION_PROOF`; a missing or malformed request token returns `400`. Clients must display and review a fresh validation report before retrying with its token, rather than adopting newer evidence during approval. Canonical object-key ordering keeps identical evidence stable across PostgreSQL JSONB serialization; array order and substantive evidence remain significant.
