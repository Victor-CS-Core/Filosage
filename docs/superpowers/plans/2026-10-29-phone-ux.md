# Phone UX implementation plan

Goal: make the existing application comfortable and understandable on phones, release the verified improvements, then evaluate Spark separately under the linked outcome checklist.

Architecture: retain the shared shell, native dialogs and lesson workspace. Add focused mobile stylesheets after existing styles, reduce duplicated navigation, and share visible-viewport sizing between dialogs. No framework, data or generation-policy changes.

Spec: [outcome checklist](../../releases/2026-10-29-mobile-ux-spark.md).

Research: [WCAG reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) motivates 320 CSS px without page-wide scrolling; [44px enhanced targets](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html) are our comfort goal (not the AA minimum); [MDN mobile accessibility](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Accessibility/Mobile) informs readable controls; [VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport) explains keyboard shrink independent of layout viewport. Preserve zoom; 16px editable controls and 14px supporting text are product baselines, not asserted WCAG requirements.

Observed production at 390×844: lesson chrome obscures the entire first exercise; activity tabs scroll horizontally with truncated labels; create examples are 32px high with 11.2px text; repeated create introductions consume most of the viewport; center navigation action is unlabelled. Screenshots retained outside Git.
