# Model evaluation budget boundary

This module is a source-level transport guard. It is not an enabled provider evaluation, a price recommendation, or proof that the complete evaluation HTTP contract is implemented. Course/lesson route composition, durable lesson stages, capability registration and end-to-end acceptance remain required before advertising the capability.

An evaluation request must supply the evaluation flag, exact build SHA, profile and operation ceiling. `FILOSAGE_MODEL_EVALUATION_APPROVAL` must contain a strict version-1 approval for one owner, unexpired build/profile, immutable course and lesson configuration fingerprints, explicit model tariffs and bounds, moderation tariff, and rate version. There are no default prices or approvals. `SITE_VERSION` must equal the approved SHA. Test values are synthetic and must never be used as real approval.

Bind an active `GenerationLease` before an SDK call. Binding and each transport admission use the real operation/account-generation/attempt/accounting-lock transaction. Wrap each Responses call with its explicit kind, configured profile and prompt version. Each call must use the approved exact model identifier, `store: false`, `service_tier: "default"`, bounded output and text-only input. Streaming, background work, previous-response reuse, unknown tools, alternate endpoints and automatic SDK retries are rejected. Moderation has a separate durable call and receipt.

Before dispatch, the global ledger reserves the worst reviewed input tariff times its reviewed maximum input count, requested maximum output, and bounded web-search call fees. The actual serialized request must fit the input bound conservatively by UTF-8 bytes. **A price/configuration reviewer must establish that `maxInputTokens` covers the entire billable input of the response, including tool-result/context processing; the request byte check alone does not establish this for tool calls.** Model identifiers must be pinned or match the returned provider model exactly. Until those bounds and current tariffs are verified, approval must remain absent. This module does not discover or infer model prices/context limits.

Input tariff categories are combined using integer arithmetic before rounding up; output is rounded separately. Admission includes every outstanding reservation under one operation ceiling. Terminal receipts must include the exact model, default service tier, response ID, supported output inventory, disjoint cached/cache-write counts, and usage within the reviewed bound. Unknown, malformed, over-bound or interrupted outcomes retain the full reservation and block further dispatch. A later successful receipt can settle after account deletion in global-only accounting without recreating private account records. No automatic reconciliation guesses or paid retries are provided.

The durable ledger stores selected usage samples, request/configuration fingerprints and bounded metadata, not prompts or raw provider bodies. Evidence is read through operation ownership. The provider's response object is only returned to the SDK after settlement succeeds. Operators still need independent provider billing reconciliation for ambiguous outcomes; changing the approval cannot release an old reservation.

Verification uses the real installed OpenAI SDK and document-store transactions with a synthetic fetch transport. It covers concurrent admission, stale and replaced attempts, lost accounting ownership, late deletion settlement, moderation, rounding, unknown usage/tier/tools, immutable approval and unsupported request rejection. These tests incur no provider cost and do not establish live model quality or live pricing accuracy.
